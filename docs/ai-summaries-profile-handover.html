Handover for the testing team. Source: prod analysis (org ID 00D80000000aRUXEA2, run 12 Nov 2026), counts are active standard users. Page list is from SF Master. Nothing has been changed in any org.

What gives a user access

All three must be true. Editing the pages alone is not enough.

  1. Page: the new component (aiAccountSummary, opportunitySummary) sits on the Account or Opportunity page the user is routed to. Plan: add it to every page that holds accountAISummary or opportunityAISummary.
  2. Permission set: the user holds AI_Reporting_Tool, which grants the AI_Reporting_Access custom permission used by the page visibility rule and the Apex class access.
  3. Feature toggle: GCP_Feature_Toggle__c resolves to on for the user (user row, then profile row, then org default). Opportunity is off on 3,416 active user rows today, so those rows must be updated, and profile rows must be created or updated for users without a user row. Account depends on the Account deploy planned for the week after this note.
